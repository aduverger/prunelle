## Server

- One Go binary, Linux first, portable to macOS (later embeddable in the desktop app). No Linux-only code paths; CI cross-builds `darwin/arm64`.
- SQLite via pure-Go `modernc.org/sqlite`, WAL, one writer connection plus reader pool, short transactions, portable SQL.
- Hand-written OpenAPI 3.1 is the contract; Go server/client generated by `oapi-codegen`, TypeScript client generated for the UI.
- REST under `/v1`, structured error envelope, `ETag`/`If-Match`, `Idempotency-Key`, SSE at `/v1/events`.

### Access

- Listens on `127.0.0.1:<port>`; exposed on the tailnet with `tailscale serve --https=443 http://127.0.0.1:<port>` (no unix socket, no sudo).
- `Tailscale-User-Login` must match the machine's Tailscale owner or a login allowed in the server config file.
- Loopback requests without Tailscale headers are the owner. Every local process on the server machine is trusted.

### Snapshots

- Per repository: configured base ref, base = merge-base(`HEAD`, base ref), `HEAD`, branch, worktree state and fingerprint, changed-file entries (path, old path, status, modes, binary flag, Git blob IDs), and full base/head contents of changed files as content-addressed blobs in SQLite. No unified-diff text is stored; diffs derive from contents.
- Untracked files are included by default (respecting `.gitignore`), labeled `UNTRACKED`, per-repo opt-out.
- Text files up to 1 MB are stored; binary or larger files are listed with a warning. A revision over ~50 MB of new content fails with an explicit error.
- Capture verifies repository state before and after; retries, then marks the snapshot inconsistent.

### Reviews and review content

- A review owns its canonical repository membership and optional cwd context. There is no named workspace lifecycle or required discovery/path allowlist. All authenticated callers are trusted with server-readable Git sources (D10).
- Review content (topics, intents, changes, findings, evidence, representations, attention) enters through a JSON review manifest: `prunelle review import` or the API, `origin=IMPORTED`. Every record carries its author (actor) and the provenance the author declares (`MEASURED`/`OBSERVED`/`INFERRED`/`UNKNOWN`).
- Until M4 the coding agent pushes manifests to Prunelle; from M4 Prunelle also calls the agent through `PiAgentAdapter`.

### Rex

- Through the `rex` CLI (`rex api call`, `rex events --json`), always `--autostart=false`; record Rex API revision.
- One Rex block = one `RuntimeSession`. `pwd` inside review source suggests an association; association is always explicit.
- The server starts and serves reviews without Rex.

## Client

- React + Vite web UI bundled into a MyGo desktop app; the server serves only the API.
- Diffs: Pierre CodeView/annotations from stored base/head contents, Highlights with capability fallback, inline code discussions and left comment navigation. Decisions and optional session integrations open on demand, not in a permanent right column. Diagrams: ELK.js layout, escaped SVG, no model-supplied HTML.
- Engineering, Design, Source perspectives as built-in presets; perspective and layout persisted locally.
- No topic editing UI in M2; captures are triggered manually.
- Plain-browser mode only for development and Playwright tests.
