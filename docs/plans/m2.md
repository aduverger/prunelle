## Goal

Open a multi-repository feature review in a React + Vite UI inside a thin MyGo desktop shell. Navigate topics, findings and all source changes; trace explanations and diagrams to immutable evidence; discuss a topic or exact code range; submit revision-specific decisions. Review remains usable without Rex or agents.

## Existing sources of truth

- `server/api/openapi.yaml`: generate TypeScript types and use a typed REST client. No parallel UI domain model.
- Topics, representations and evidence are read through existing endpoints. Representation availability and source-file topic membership come from the server, not reconstructed in the client.
- Discussions use server-provided `topic_ids`, typed anchors, versions and immutable messages. Decisions are human-authored and explicitly select a revision.
- SSE events invalidate authoritative queries; reconnect always refetches. Session health/runtime associations use M0b endpoints independently of review loading.

## Scope

1. **Shell and transport.** Independent `client/` Go module and frontend. Pin MyGo; bundle built Vite assets. Use MyGo's streaming fetch plugin for REST and SSE, restricted to loopback HTTP(S) or Tailscale HTTPS API targets. No server CORS changes or credentials. Browser mode is development/testing only, with a fixed Vite proxy target.
2. **Navigation.** Review picker, revision picker and manual capture; topic hierarchy with manual/attention ordering; Findings and All Source Changes tabs, always exposing Unassigned Changes and every repository.
3. **Shared selection.** Topic, evidence/finding and exact code-range selection survive view switches. Text/Diagram/Code/Evidence renderers can be shown alone or two at a time. Multiple stored representations remain selectable. ELK lays out escaped SVG nodes/edges; Pierre Diffs displays stored base/head files and line selection.
4. **Grounding.** Show intent vs observed changes vs findings separately, authors/provenance, attention rationale/uncertainty, snapshot warnings and explicit unavailable states. Evidence links and diagram nodes open canonical evidence/source, not synthetic content. Evidence from an older revision is labeled and opens that revision's snapshot.
5. **Discussion/decision.** One shared discussion panel across views; topic, finding, evidence, diagram-node and code-range anchors; replies, resolve/reopen with If-Match; review-wide discussion access. Preserve drafts on transient failures; reuse an idempotency key for an unchanged retry. Decisions COMMENT/APPROVE/REQUEST_CHANGES with actionable selections and revision-specific history.
6. **Preferences and sessions.** Persist perspective, one/two-view layout and desktop server address locally. Engineering favors attention/diagram+code, Design intent/text+diagram, Source exhaustive files/code. Sessions panel polls optional backend health and runtime sessions, shows explicit vs suggested workspace links and supports explicit association/removal; never launches/stops a process.

## Failure behavior

Keep last loaded content during disconnection and show status/retry. SSE reconnects with its last event sequence and refetches on ready. Do not silently retry writes with a new key or silently re-anchor a draft after capture/navigation. Reject stale resolve/reopen cleanly and reload the thread. Old revision source is immutable; topic/representation metadata remains the current graph (revision-aware comparison is M3).

## Decision ledger

Choices made where the spec was silent, least confident first.

1. **Desktop endpoints are loopback HTTP(S) or Tailscale HTTPS MagicDNS names only.** Redirects are refused. Custom reverse-proxy domains and raw remote IPs are not supported. Would have asked whether those deployment forms are needed now; the accepted Tailscale Serve setup uses MagicDNS.
2. **Minimum packaged macOS version is 13.3**, consistent with the frontend's Safari 16.4 build target. MyGo v0.8.3 and its matching fetch/runtime packages are pinned. Native Linux/WebKit validation justifies retaining MyGo instead of switching to Electron; native macOS validation is still needed.
3. **Engineering sorts siblings by explicit attention; Design by linked intent count; Source uses exhaustive file navigation.** Manual order is always selectable. No inferred severity score, grouping rewrite or hidden topic filter. Would have asked about preferred default composition; defaults are Diagram+Code, Text+Diagram, and Code+Evidence respectively.
4. **Discussion and reply drafts are memory-only**, retained across view/perspective/filter switches and recoverable network errors. New-discussion anchors freeze on first edit; decision drafts keep their original revision until explicitly changed. Leaving the review/server or reloading warns about text drafts. There is no persistent draft/outbox system.
5. **Unchanged explicit retries reuse their idempotency key in the current form.** No automatic write retries. A 409 unknown outcome remains visible for the reviewer to inspect rather than silently minting a new key. Success resets the form/key; structured errors preserve drafts. Inputs stay disabled through submission and the post-write refresh, so late completion cannot erase a newly typed draft. Stale resolution reloads authoritative state and requires another explicit action.
6. **Sessions poll every five seconds only while the panel is open.** M1 deliberately emits no session events. Lists include all observed runtimes so a reviewer can explicitly associate even a non-suggested runtime. Associations never launch or stop a process.
7. **Preferences use localStorage**, scoped to the UI origin: perspective, view pair, split layout and desktop server URL. Unavailable/corrupt storage falls back to defaults. Development and packaged apps have separate preferences; records themselves are never cached persistently in the client.
8. **All supported discussion anchor types can be read independently of views.** UI entry points include review/topic, canonical intents/changes/findings, evidence, diagram nodes and exact code ranges. Source line ranges remain one-sided; the server resolves immutable selected text. Multiple representations of one type are selectable.
9. **Markdown is rendered without raw HTML or remote images; diagrams are structured escaped SVG.** Test output and artifacts remain literal text. No screenshots or validation evidence are fabricated when missing.
10. **Source revision selection does not version the topic graph.** The UI labels this explicitly. Evidence opens its own revision's file, and original code-range discussion anchors never move. Topic/representation comparison and re-anchoring remain M3.
11. **No server/schema change.** Workspace/review creation and manifest import stay in the CLI/API. M2 adds manual capture but no topic/representation editing UI or agent integration. The client sends no agent-identity header.
12. **Native automation is test-only**, behind the `e2e` build tag and an explicit local socket. The smoke runner creates disposable server data/repos and isolated app storage; it disables the WebKit sandbox only in that restricted test subprocess, not in production builds.

## Implementation notes

- `client/` is an independent Go module plus a pnpm-locked React/Vite frontend. `main.go` embeds the production frontend and registers MyGo's fetch plugin. `mygo.json` packages the same assets into a desktop app.
- `src/api/schema.d.ts` is generated from the existing OpenAPI contract. `openapi-fetch` handles typed REST calls; TanStack Query owns request state/refetching, and `eventsource-parser` handles streamed frames.
- One review selection feeds topic navigation, the two renderers and the discussion panel. The UI uses the API's representation availability, evidence IDs, source-file membership and discussion `topic_ids` directly. ELK handles constrained diagram layout; Pierre Diffs renders stored contents and selects line ranges.
- SSE reconnects after one second, resumes after the last sequence, and invalidates authoritative queries on ready and every event. Last successful review data stays visible during disconnection. Runtime queries remain independent.
- CI adds generated-type freshness, formatting/lint/unit checks, a production frontend build, desktop Go checks/cross-build, real-server Playwright and the bundled Linux/WebKit smoke test.

## Follow-up implementation decisions

No product behavior or API contract changed. These are implementation-only choices, least-confident first:

1. SSE uses the same typed OpenAPI client as REST (`parseAs: stream`), rather than a second desktop/browser base-URL and fetch path. The stream helper exposes only the sequence its consumer needs; ready/event invalidation, resume, cancellation and reconnect timing stay unchanged.
2. View types come from the generated representation schema; default views come from the Engineering preset. Topic ordering has one local type instead of repeated unions. No presentation rules changed.
3. Retain the write/idempotency hook, frozen draft anchors/revisions, and mounted-but-hidden discussion/decision forms: each addresses exercised retry, stale-version or draft-preservation behavior. Remove only the unused client-side error-code field and pass-through file-selection callback; use direct branches for multi-way rendering/state choices and one predicate for text-draft warnings.

Refactoring validation passed: generated-type freshness, Prettier/ESLint, TypeScript/production build, two unit tests, client Go formatting/vet/race tests and darwin/arm64 build, all five real-server Playwright scenarios, and the bundled native Linux/WebKit smoke test. At that point, test files, server sources, API schemas and dependency locks were unchanged.

## Stored code-range request correction

A regression through the real API showed that comments created directly from linked evidence, or from a reopened code-range thread, sent response-only `blob_hash` and `selected_text` fields back to a closed request schema and received 400. The code-comment entry point now projects only the five documented input fields. This preserves the original revision/repository/path/side/lines and lets the server resolve authoritative text and blob identity; it does not weaken the API schema or re-anchor anything.

The regression exercises both origins without reselecting a gutter line, including reopening an original anchor after a new capture changes the file. The reconnect scenario also writes a discussion while the browser is offline and requires it to appear on reconnect, before another live change occurs. Preference-test global stubs are restored after failures as well as success. No existing protection was removed.

Correction validation passed: the new regression failed with 400 before the payload correction and now passes for both evidence-loaded and reopened ranges. All six Playwright scenarios, two unit tests, native Linux/WebKit smoke, formatting/lint/typechecked build, generated-type freshness, client/server Go vet/race checks and darwin/arm64 builds pass. Native macOS launch/signing, real tailnet streaming and live UI association remain unverified as listed above.

## Independent thread-action retry identities

A committed reply whose response is lost must retain its idempotency key even if the reviewer resolves or reopens its thread before retrying. Replies and status changes now use separate instances of the existing write hook. Their busy states remain combined, so reply text, Reply and Resolve/Reopen stay disabled while either request/refetch is running. No server/API change, automatic retry, new hook option or generic key registry is needed.

Implementation choice where presentation was unspecified: retain errors from both independent actions in the existing single alert, rather than hiding an unresolved reply error when a status change succeeds.

The focused real-server regression drops a committed reply's response, resolves the thread, and retries the unchanged reply. Before the correction it produced two immutable replies; afterward it must reuse the original key, clear the draft and leave exactly one persisted reply.

Thread-action validation passed: the focused regression first demonstrated two persisted replies before the correction, then passed with one reply and the original retry key. All seven Playwright scenarios, two unit tests, formatting/lint/typechecked production build, generated-type freshness, client Go vet/race checks, native Linux/WebKit smoke, darwin/arm64 cross-build and Linux/macOS packaging pass. The existing native macOS/tailnet/live-association validation gaps remain.

## Pierre reuse decision ledger

Implementation choices where unspecified, least-confident first:

1. **Pin Trees 1.0.0-beta.6**, the published release evaluated. A scoped pnpm override uses the same `@pierre/theming` 1.0.2 patch already used by Diffs; Trees' exact 1.0.0 dependency otherwise declares an incompatible optional theme peer. Frozen installation and peer checks must pass. Would have asked whether using the prerelease or waiting for a stable release was preferred; adopting Pierre Trees was explicitly requested.
2. **Each repository has bounded, initially expanded trees in both source groups.** The full folder hierarchy starts expanded; the viewport grows with Pierre's visible row count up to 320px, reserving 48px for its built-in search field and spacing. No custom folder projection, sorting, search, virtualizer, row renderer or keyboard handler. Would have asked whether a single larger source pane was preferred to per-repository trees; separate models preserve unrestricted repository labels and exact paths without aliases.
3. **Deleted files are a separate subtree per repository/group.** A real Git fixture replacing `README.md` with `README.md/replacement.txt` first reproduced Pierre's file/directory collision error. Separating the server's `DELETED` entries from head-side changes allows both original paths and contents to remain inspectable, including the inverse replacement. This is not a filter or filesystem mutation; counts still include every entry.
4. **Prunelle's revision/repository/path/range remains the shared selection.** Pierre supplies selected paths, not DOM focus, and its `useStableCallback` keeps callbacks current. The last selected path opens a file when it matches a canonical source entry; directory selection does not replace the active file. Opening navigation on an evidence-selected file must not erase its range. An old-revision anchor must not highlight or switch to a newer revision's same-named file. Models reset only on revision or actual displayed path/status/unassigned changes; unrelated refreshes retain expansion and selection.
5. **Keep semantic topics and evidence-range links outside Trees.** Its supported API has no separate topic ID/display label or arbitrary row-label renderer. No title encoding, fabricated filenames, shadow-DOM modification or replacement generic tree framework. Domain-only Unassigned and Type changed markers use Pierre's decoration slot; Git icons/statuses remain Pierre-rendered. `TYPE_CHANGED` uses its modified color with an explicit type-change marker, retaining the original status in the diff header.
6. **Use Diffs' repository prefix and status suffix slots**, preserving its native filename, rename rendering and diff statistics. Only binary/omitted files retain a plain filename header because they have no text diff. Snapshot identity and the existing line-selection/discussion flow are unchanged. No server/API/schema changes.
